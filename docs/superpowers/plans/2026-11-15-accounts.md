# Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Optional username accounts on the combined site, so the five saved things (Anime ratings, Anime settings, Anime Watch together friends, Games ratings, Games settings) follow a person to any device. Ratings are merged one by one by their date, so no rating is lost.

**Architecture:** The Worker (`anything-scout/worker`) gets a D1 database and `/api/account/*` routes: create, sign in, sign out, me, sync, picture. The browser keeps working from `localStorage` exactly as today. A shared sync engine in `web/src/shell/account/` compares each section's stores with a saved "last synced" snapshot, sends the differences, and applies what comes back. Server rows carry a per-user revision number, so each sync only downloads what changed.

**Tech Stack:** Cloudflare Workers + D1 (wrangler 4.142.0), TypeScript 7, React 19, vitest 5.0.2, Node 24 `node:sqlite` for a fake D1 in tests, Playwright + Edge (global python) for browser checks.

**Spec:** `03 Projects/(C) Combined Site — Accounts Design.md` (repo copy: `docs/superpowers/specs/2026-11-15-accounts-design.md`)

## Global Constraints

- Free only: D1 free plan (5 GB, 5M rows read/day, 100k rows written/day). Anything needing a card on file → stop and ask.
- Username only, no password. The users table carries an empty `password_hash` column for later.
- **Usernames**:
  - 2–20 characters after Unicode NFKC + trim.
  - Allowed: `\p{L}`, `\p{N}`, `_`, `-`.
  - **Capitals count** (`Ken` ≠ `ken`). No lowercasing anywhere; full-width `Ｋｅｎ` becomes `Ken` through NFKC.
- Merge rule:
  - For each item, the newer `at` (ISO string from the device) wins; on equal `at` the server's copy wins.
  - A removal is a row with `rating: null` and its own `at`.
  - Blocks (`anime.settings`, `games.settings`, `anime.friends`): the whole block with the newer `at` wins.
- Saved-data key names stay as they are (`anime-scout.ratings`, `anime-scout.settings`, `anime-scout.friends`, `game-scout.ratings`, `game-scout.settings`). Accounts read them; they don't move or rename them.
- Signing in is optional; a signed-out site behaves exactly as today. A browser with storage blocked still works signed out.
- No delete-account or rename button.
- Exact UI copy (spec): under the username box, always shown: EN "Anyone who knows your username can open this account. Don't use your real name or anything private." / JA "ユーザー名を知っている人は誰でもこのアカウントを開けます。本名や個人的な情報は使わないでください。"
- UI: existing tokens only, no emoji, no new colors; icons from `lucide-react` (already used).
- No new npm dependencies (Radix dialog + dropdown are already in `web/package.json`).
- The dev site uses wrangler's local D1 only. Nothing in Tasks 1–8 touches the live database or deploys.
- Deploy only in Task 9, only with the user's OK: `npm run deploy:golive`, then move the `live` tag. `npm run deploy` keeps refusing.
- Commit + push after each task (private GitHub repo). Commit messages end with the session's attribution lines.
- Vault files Claude writes get a `(C)` prefix. Don't edit the user's own (non-(C)) notes.

## Review Focus

1. **A removal racing a re-rating on another device.** The later `at` must win both ways: a removal at 10:05 beats a rating at 10:00, and a rating at 10:05 beats a removal at 10:00. *(Task 2 server tests + Task 5 engine tests)*
2. **Two tabs of the same browser, both signed in.** They must not double-apply, lose a change, or corrupt the snapshot. Syncs are serialized with `navigator.locks`, and the snapshot is re-read inside the lock. *(Task 6 test with a fake lock, Task 8 browser check with two tabs)*
3. **A big import or a big Watch together list.**
   - A 600-show AniList import must sync. D1 allows 100 bound values per statement, so writes are chunked.
   - A Watch together block up to 1 MB is accepted. A bigger one gets a clear 413, and the browser keeps its local copy and shows "too big to sync".
   - *(Task 2 tests, Task 6 test)*
4. **The session disappears mid-use** (account removed by command, or a session row lost). The browser gets a 401, keeps every list it has, shows "You were signed out", and stops syncing. *(Task 6 test)*
5. **Storage blocked / private window.** Loading the account record fails, which means "signed out". The sign-in button still renders, and signing in shows "This browser can't save your sign-in" instead of crashing. *(Task 6 test)*

### Task 2: Sync route (ratings merged by date, blocks newest-wins, revisions)

**Files:**
- Create: `worker/src/sync.ts`, `worker/test/sync.test.ts`
- Modify: `worker/src/account.ts` (route `POST /api/account/sync`)

**Interfaces:**
- Consumes: `authUser`, tables from Task 1.
- Produces:
  - Types:
    - `SyncItem = {section: "anime"|"games"; item: string; rating: string|null; at: string}`
    - `SyncBlock = {name: "anime.settings"|"games.settings"|"anime.friends"; value: string; at: string}`
  - `POST /api/account/sync {rev: number, items: SyncItem[], blocks: SyncBlock[]}` → 200 `{rev: number, items: SyncItem[], blocks: SyncBlock[]}`.
    - The answer holds every row whose `rev` > the request's `rev`, after this request's changes are merged in. `rev: 0` = everything.
    - The browser's own winning rows come back too (harmless: same values).
  - `mergeRow(existing: {at:string}|null, incoming: {at:string}): boolean` = incoming wins. It wins when there is no existing row or `incoming.at > existing.at`; string compare of ISO-8601 UTC is fine because both sides write `toISOString()`.
  - Validation:
    - `item` must match `^[a-z0-9]+:[A-Za-z0-9_.-]{1,60}$`.
    - `rating` must be in `loved|liked|okay|disliked|hidden` or null.
    - `at` must parse as a date and be at most 64 chars.
    - At most 5,000 items per request; each block value at most 1,000,000 chars; request body at most 4 MB.
    - Bad input → 400 `{error:"bad_sync", message}`. A block too big → 413 `{error:"too_big", name}`. Nothing is written in either case.
  - Writes:
    - One new `rev` = `users.rev + 1` when anything wins. Rows that win get that `rev`.
    - Chunked so no statement binds more than 100 values, all in one `DB.batch` (all or nothing).
    - When nothing wins, `rev` doesn't change and there are no writes.

### Task 5: Sync engine (pure functions)

**Files:**
- Create: `web/src/shell/account/engine.ts`, `web/src/shell/account/engine.test.ts`

**Interfaces:**
- Consumes: `SyncItem`, `SyncBlock` shapes (re-declared in `web/src/shell/account/types.ts`, identical to the worker's).
- Produces:
  - `Snapshot = {rev: number; items: Record<string /* "games|steam:730" */, {rating: string|null; at: string}>; blocks: Record<string, {value: string; at: string}>}`. This is the last state both sides agreed on.
  - `planPush(snap: Snapshot, local: {items: Map<string /*section|item*/, {rating:string; at:string}>; blocks: Map<string, string>}, removedAt: Record<string,string>, blockAt: Record<string,string>, now: string): {items: SyncItem[]; blocks: SyncBlock[]}`
    - A local row differing from the snapshot → send it with its own `at`.
    - In the snapshot with a rating but missing locally → removal, with `at = removedAt[key] ?? now`.
    - A block text differing from the snapshot → send it with `at = blockAt[name] ?? now`.
  - `applyPull(local, answer: {items, blocks}, pushedNow: Set<string>): {items: Map<...>, blocks: Map<...>}`
    - Server rows replace local ones; `rating:null` deletes the local row.
    - Skip keys in `pushedNow` (changed locally after the push was planned) — they go next time.
  - `nextSnapshot(snap, answer, rev): Snapshot`.
  - `firstSignIn(local, account: {items: SyncItem[]; blocks: SyncBlock[]}): {kind: "upload"} | {kind: "same"} | {kind: "ask"; missing: number}`
    - `upload` = the account is empty.
    - `missing` = local ratings whose key is missing from the account or whose rating differs.
    - `same` = missing is 0.
  - `addChoice(local, account): {items: SyncItem[]; blocks: SyncBlock[]}` = what "Add them to your account" sends: every local rating with its `at` (the server's merge decides).
    - Blocks follow the spec: the account's settings win when the account has any blocks; otherwise the browser's go up.

### Task 6: Account client + sync runner

**Files:**
- Create: `web/src/shell/account/api.ts`, `web/src/shell/account/account.ts`, `web/src/shell/account/runner.ts`, `web/src/shell/account/runner.test.ts`
- Modify: `web/src/main.tsx` (start the runner after the stores load)

**Interfaces:**
- Consumes: Tasks 4 and 5; routes from Tasks 1–3.
- Produces:
  - `api.ts`: `createAccount(name)`, `signIn(name)`, `signOut(token)`, `me(token)`, `sync(token, body)`, `putPicture(token, blob)`, `deletePicture(token)`.
    - Each returns the parsed JSON or throws `AccountError {code: "bad_name"|"taken"|"unknown"|"too_many"|"signed_out"|"too_big"|"offline"|"server"}`.
    - A network failure maps to `offline`.
  - `account.ts`: `accountStore` (via the shell's own copy of `createStore`, or import anime's: either is fine).
    - Value: `{state: "signed_out"} | {state: "signed_in"; name; token; pictureAt: string|null; synced: string|null; status: "ok"|"offline"|"too_big"} | {state: "ended"; message: "signed_out"}`.
    - Persisted under `anything-scout.account`: `{name, token, pictureAt, snapshot, removedAt, blockAt, stash: LocalSnapshot|null}`.
    - Loading it with blocked storage → signed out (Review Focus 5).
  - `runner.ts`:
    - `startSync(deps = realDeps)`. Subscribes to every adapter.
      - On rating changes it records `removedAt[key] = now` for rows that vanished.
      - On block changes it records `blockAt[name] = now`.
      - Changes applied by the runner itself are skipped, using a "applying" flag.
    - Triggers: load, 3 s after the last local change, `visibilitychange` → visible, `online`.
    - Each sync runs inside `navigator.locks.request("anything-scout-sync", ...)` and re-reads the persisted record inside the lock (Review Focus 2). Without `navigator.locks`, an in-tab flag.
    - The answer → `applyPull` → adapters' `replace` → `nextSnapshot` → persist.
    - Errors:
      - `signed_out` → state `ended`, the lists stay as they are (Review Focus 4).
      - `offline` → status `offline`, retry on the next trigger.
      - `too_big` → status `too_big`; the local lists are kept and the other blocks still sync.
    - `signInFlow(name, mode: "create"|"signin"): Promise<{kind:"done"} | {kind:"ask"; missing:number; resolve(choice: "add"|"leave"): Promise<void>}>`
      - It does a `rev: 0` pull without pushing, then `firstSignIn`.
      - `upload` / `add` → push (`addChoice`).
      - `leave` → `stash = snapshotLocal()`, then the account's lists replace local ones.
    - `signOutFlow(): Promise<{kind:"done"} | {kind:"unsynced"; count:number; force(): Promise<void>}>`
      - A last sync is tried first. If changes still haven't been sent, it returns `unsynced` so the menu can ask "3 changes haven't synced yet. Sign out anyway?" (Claude's call).
      - Then: server signout (best effort), `stash ? restoreLocal(stash) : clearLocal()`, and the record is deleted.
  - The runner takes `deps: {api, now, lock, storage, adapters}` so tests use fakes.
